### 第一步：检查仓库状态及分支

3. 不自动合并到 `develop` 或 `main`，不自动推送；先把实现及检查结果交给用户验收。

### 第二步：优先写功能代码

建立最小可运行的纯 TypeScript 工程和 `src/domain/` 模块，避免与未来 Expo 目录冲突。为了运行 TypeScript，只安装必要的最少依赖、配置最简单的 `typecheck` 和轻量测试命令；不要引入 Redux、Zustand、SQLite、Expo、UI、CI、复杂代码生成等不属于本阶段的东西。

本次必须实现：

1. **Money 基础**：HKD、CNY、MOP、TWD、USD（2 小数位）和 JPY（0 小数位）；严格解析用户金额字符串成最小单位安全整数；金额格式化；拒绝非法小数位、负费用、非有限值和溢出。金额计算不得直接用浮点数乘比例后累计。
2. **稳定均分**：指定稳定成员 ID/顺序，金额按最大余数法分配；HK$100 / 3 为 `33.34/33.33/33.33`，JPY 100 / 3 为 `34/33/33`；重算结果一致、改显示名称不改变结果。
3. **单老板请客**：一位老板按固定金额或固定比例承担费用；提供“老板是否继续参与剩余均分”的选择；请客金额不得超出账单；请客承担与真正向商家付款明确分开。例：5 人 HK$1,000，老板承担 HK$600，默认其他 4 人各 HK$100；老板也参与剩余分摊时老板 HK$680，其他各 HK$80。
4. **业务结果与错误**：输出可供未来 UI 使用的每成员金额、币种、简要计算说明和稳定结构化错误码；所有分配金额合计必须严格等于输入总额；不要直接拼接 UI 的中英文文案。

本次**先不要实现**：逐项消费、多人老板、自定义比例和份数、多笔活动合并、商家退款、成员还款、SQLite、结算建议、StoreKit、PNG、页面。这些放到后续 Phase 1B/1C/2–6。

### 第三步：仅做轻量验证

请完成实际开发后再添加少量针对本阶段的验证即可：

- 港币 100 / 3 的均分与日元 100 / 3 的均分。
- 请客 600 / 1000 的两种剩余分摊情形。
- 至少一例非法金额/溢出被拒绝；确认计算总和守恒。

约 **5–8 个有价值的断言或测试用例**即可，不需要提前实现 PRD 98 项测试、随机属性测试、复杂压力测试、UI 测试或覆盖率门槛。

最后运行可用的 `typecheck`、少量针对性测试及 `git diff --check`。有现成 lint 才运行 lint。缺少环境就客观说明，不要宣称未执行的测试通过。
