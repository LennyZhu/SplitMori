## 2. 數據來源及計算

- 從**同一次一致的 SQLite 讀取快照**獲取活動狀態、成員列表、有效費用、商家付款、有效退款、實際成員還款、歷史修訂及作廢事件後的活動帳本；優先復用 `getActivityLedger`、現有 `activityDetail.ts` 等服務，避免在 UI 分別查多次造成數字不一致。
- **直接使用既有 `calculateBalances()` 的結果**。每位成員的淨額規則：實際商家付款 − 實收商家退款 − 應承擔費用 + 已付成員還款 − 已收成員還款。顯示時將實收退款和已付／已收還款分開，勿混成一欄。
- **直接使用既有 `suggestTransfers()`** 並保持其確定性順序/尾差。不得聲稱「數學最少轉帳筆數」；只說「轉帳建議」。不產生真實還款事件。
- 金額用現有最小單位整數及格式化函數；只處理活動本身幣種，禁用浮點數自行重算；確保正負方向、正負零、JPY 等零小數幣種顯示正確。
- `尚待結算` 可以依淨額正方加總（亦等於負方絕對值和）；`已登記還款` 為**實際已記錄事件**的有效金額，不能當作費用或減少活動有效支出。注意作廢事件處理。
- 費用修訂採用當前有效費用版本；有效商家退款扣除已作廢退款；成員還款同樣排除已作廢紀錄；既有真實付款和退款接收成員的方向均需正確。
- 同時顯示**活動狀態**（進行中／已完成）和**結算狀態**（未結清／已結清），兩者不混同。已完成但未結清必須仍可查看結算。
- 有 0 筆財務事件時優先顯示「暫無財務紀錄」空態，避免讓用戶誤認已曾經付款或完成結算；已有紀錄且全部淨額為零時才清楚顯示「款項已全部結清」。

## 3. 三個選項卡

### A. 結算總覽（預設）
- 顯示活動名稱、日期、幣種、活動狀態。
- 活動有效費用、費用筆數、有效商家退款、已登記的真實成員還款。
- 目前尚待結算金額、建議轉帳筆數，清楚區分「活動有效費用」和「尚待結算」（前者不隨會員間還款減少）。
- 列出**所有活動成員**：姓名、正淨額「應收」、負淨額「應付」、零淨額「已平衡／淨額 0」。新加入但未參與財務事件的成員仍需展示。
- 可切換到「轉帳建議」，不生成付款紀錄。

### B. 每人收支
- 按真實活動成員順序逐一列出，可展開/收起。
- 展開項顯示：對商家實際付款、實收商家退款、應承擔費用、已支付成員還款、已收到成員還款、目前淨額。這些欄位均由既有账本推導，不能為方便畫面拼湊假值。
- 原有歷史事件影響依既有算法計算，金額顯示須和總覽及 S07 一致。
- 成員列表長時可捲動，允許多個零餘額成員。

### C. 轉帳建議
- 顯示仍需結算的總額與建議清單（付款成員 → 收款成員 → 建議金額）。
- 清楚顯示「建議不等於已付款，需實際轉帳並另行記錄還款」的提示。
- 無建議時顯示對應空態；若有歷史財務但全員淨額為 0，顯示已結清；若無歷史則顯示尚無需結算的空態。
- 高保真中的「記錄還款」是**未來 S10**：本階段只提供清楚標記的開發中入口/提示（或安全禁用的說明），**不能假裝按下就已經完成還款**。
