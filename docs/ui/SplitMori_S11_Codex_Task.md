# Codex 任务：SplitMori S11 活动结算 PNG 分享（V3.2 最终版）

## 目标与边界
在现有 `develop` 分支完成 **S11 Free 活动结算 PNG**：从 S09「活動結算」进入预览，生成真实 SQLite 活动结算静态图片，支持保存 iOS 相簿和系统分享。沿用冻结的 PRD/ADR、现有 S09 Finance/Settlement 服务和已实现的快速分账 PNG 基础。**不要实现 Pro 高级模板、单独模板设置页、S12/S13 或重构财务算法。**

## UI（高保真已定，不再自由设计）
- 01：S09 原页面新增清晰的「生成結算圖（PNG）」次级入口；保留原有结算操作和底部按钮。
- 02：独立「結算圖預覽」，显示**整张导出 PNG 的真实预览**，支持长图预览（滚动或缩放），底部「返回結算」「儲存或分享」。Free 只有标准黑白模板，**不要额外设置页**。
- 03：保存或分享操作。支持「儲存到相簿」「系統分享」「重新生成」。重新生成时重新读取最新账本生成新快照；普通保存/分享始终使用当前预览对应的**同一份已生成图片**，不能悄悄换数据。
- 04：相簿保存经系统确认成功后才出现成功提示；权限拒绝、取消、失败分别处理。分享调起系统分享面板，不把面板关闭当作发送成功。
- 05/06：活动 **已完成未结清**、**已结清** 都可导出，状态与账务分别正确展示；这是状态示例，不新增页面入口。
- 导出图：采用正式参考的**精致收据式**布局：品牌 + 活动名/日期/币种 + 两个独立状态 + 显著“尚待結算” + 有效费用 + 有效商家退款 + 有效成员还款 + 每位成员应收/应付 + 全部转账建议 + 快照非真实支付声明。视觉色值 `#FDFCFB/#FFFFFF/#282828/#E7E5E2`，不用旧版大灰卡报表。

## 数据与财务安全
- 数据必须取自 S09 使用的**同一套现有 Finance/Settlement 只读查询**，原子/一致快照优先；不能在 UI 重新实现结算与转账计算，更不能硬编码示例成员和金额。
- PNG 生成、保存、分享 **不写 SQLite 财务事件**，不自动生成真实还款，不改变活动状态，不改变费用/退款/修订历史，不将建议转账视为已付款。
- 活动状态（进行中/已完成）与财务结清状态（未结清/已结清）独立展示；待结算为 0 时不生成虚假的转账建议。使用现有结清判定及金额格式化约定，不自行以屏幕浮点数判断。
- 多币种 HKD/CNY/MOP/TWD/USD/JPY；金额整数最小单位及正确小数位（JPY 为 0 位）；完整 zh-HK/en 文案与日期显示；长姓名、很多成员、长转账列表时完整导出不裁切。
- 没有费用、没有待结算、没有转账建议、已完成未结清、已结清均有合理的显示；失败不影响 S09 基础结算。

## 技术实现
- 优先审查并复用快速分账 PNG 使用的导出方法（view-shot/图片保存/分享/权限），需要新增依赖时先核对 Expo SDK 58 兼容性。
- 图片必须是清晰的实际 PNG（不把屏幕截图连同导航、Tab、按钮一起导出）；画布宽度与高度适配文本及列表，白底、字体清楚。
- 预览与导出的图片**内容一致**；临时文件与异常处理遵循现有项目做法，避免遗留大量文件。
- 权限拒绝、生成失败、保存失败、系统分享不可用/取消要正确处理；禁止误报保存成功。只做必要变更，不改已验收的 S01–S10/3B7A/3B7B 业务逻辑。
